# 第四部分：写作风格与表达指南

## 4.1 学术表述模板

**数据引用**：
- "由表 X 可知，..."
- "如图 X 所示，..."
- "结果表明，..."
- "经计算，..."
- "对比分析发现，..."

**方法描述**：
- "采用 XXX 方法对 XXX 进行求解"
- "基于 XXX 原理，建立了 XXX 模型"
- "通过 XXX 变换，将 XXX 转化为 XXX"

**结论陈述**（在证据允许时给出数值）：
- "XXX 与 XXX 的偏差为 X%，相对于预先定义的 Y 标准可接受/不可接受"
- "在当前参数范围内，XXX 的灵敏度指标为 X，影响方向为 Y"
- "按所述方法得到的 95% 置信区间为 [X, Y]"

## 4.2 禁止表达（国一论文中几乎从不出现）

| 禁止 | 原因 | 替换方案 |
|------|------|---------|
| 深入探讨 | 空洞修饰 | 删除 |
| 充分证明 | 空洞修饰 | 用具体数值替代 |
| 明显看出 | 主观判断 | 删除，直接陈述事实 |
| 显而易见 | 主观判断 | 删除 |
| 具有重要意义 | 空洞修饰 | 用具体数据支撑 |
| 广泛关注 | 空洞修饰 | 删除 |
| 成为热点 | 空洞修饰 | 删除 |
| 通过深入分析 | 空洞修饰 | 删除"深入" |
| 系统研究 | 空洞修饰 | 删除或用具体内容替代 |
| 较好结果 | 模糊表述 | 给出具体数值 |
| 令人满意 | 模糊表述 | 给出具体数值 |
| 我们来看 | 口语化 | "接下来分析" |
| 非常好 | 主观评价 | 给出具体数值 |

## 4.3 段落结构原则

- 一个段落围绕一个清晰主题展开；长度由论证需要决定
- 需要时用主题句明确本段任务，然后给出方法、证据和解释
- 段落间用过渡句连接
- 关键公式首次出现时解释变量、作用和适用条件
- 图表在正文中必须被引用，并解释与当前论点直接相关的发现
- 避免没有结构的长段落、单句堆叠和无论证用途的留白

## 4.4 好表达 vs 差表达对比

```
差：模型精度较高，结果令人满意。
好：交叉验证偏差为 X%，低于事先给定的 Y% 接受标准。

差：参数 A 对结果影响很大。
好：在给定扰动范围内，参数 A 的灵敏度指标为 X，影响方向为负。

差：我们来看一下图 3。
好：如图 3 所示，主峰位于 X；在预设检测阈值下未发现显著次峰。

差：模型具有较好的稳定性。
好：在已说明的抽样次数和分布假设下，输出的 95% 区间为 [X, Y]，区间宽度为 Z。
```

# 第五部分：评阅要点对标

下表是常见评阅关注点的观察总结，不代表官方权重或奖项分界。

| 评阅维度 | 有效证据组织 | 常见不足 |
|---------|------------|------------|
| 问题理解 | 每个子问题明确数学目标、输入输出和相互依赖 | 仅复述题面，未指出数学任务 |
| 模型建立 | 推导覆盖支撑结论所需的关键步骤，变量与物理/业务意义清晰 | 推导跳跃，假设与公式脱节 |
| 模型求解 | 算法描述可复现，并结合本题变量、约束和停止条件 | 只给通用算法名称或代码截图 |
| 结果分析 | 图、表和文字围绕同一论点，数值可追溯 | 只放图不分析，或文字与图不一致 |
| 模型检验 | 检验与模型目的和风险匹配，失败结果被解释 | 堆砌无关指标，或缺少关键验证 |
| 敏感性分析 | 覆盖高风险参数并说明现实扰动范围 | 参数范围无来源，或结论只凭图形 |
| 论文规范 | 遵循本届官方文件，编号、引用和匿名性一致 | 把经验格式误当官方硬规则 |
| 创新性 | 方法选择有理由，改进解决了可验证的具体缺陷 | 模型堆砌，创新点无法验证 |

# 第六部分：团队协作写作流程（国一经验）

## 6.1 分工与沟通

```
建模手 → 论文手：
- 将自己手写的建模公式解释给论文手
- 怎么想到的？为什么用这个公式？每个字母是什么含义？
- 说清楚，这样效率很高

编程手 → 论文手：
- 将算法步骤解释给论文手
- 为什么要用这个算法？原理是什么？结合本题的步骤是什么？
- 不能"把一堆代码扔给论文手"

论文手 → 建模手/编程手：
- 不清楚的地方主动问
- 论文写不下去时，往往是因为建模手/编程手没有解释清楚
```

## 6.2 论文写作顺序（国赛经验）

**推荐写作顺序**（不是从前到后！）：
1. 先写**模型建立与求解**（核心内容，篇幅最大）
2. 再写**六、模型检验**（依赖模型结果）
3. 然后写**二、问题分析**和**三、模型假设**、**四、符号说明**
4. 接着写**问题重述**（此时对问题理解最深）
5. 再写**模型评价与改进**和**结论**
6. 最后写**摘要**（此时对全文理解最完整，按证据反复压缩和核对）
7. 最后检查**参考文献**和**附录**

## 6.3 常见沟通问题

| 问题 | 表现 | 解决方案 |
|------|------|---------|
| 建模手说不清楚 | 论文手写不出公式推导 | 建模手写下来，逐行解释 |
| 编程手只给代码 | 论文手只能从网上找通用流程图 | 编程手画出结合本题的算法步骤 |
| 论文手等米下锅 | 论文进度停滞 | 建模手和编程手先给"草稿版"文字 |
| 三人各做各的 | 没人知道别人在做什么 | 每天至少 2 次同步（上午、晚上） |

# 第七部分：常见降分陷阱与避坑指南

## 7.1 致命错误（直接降档）

1. **摘要没有数值结果**：评为"摘要不合格"，直接降档
2. **结论与摘要数值不一致**：评为"论文不严谨"，直接降档
3. **缺少灵敏度分析**：评为"模型不完整"，至少降一档
4. **公式推导跳跃太大**：评为"模型建立不严谨"
5. **图表后没有分析文字**：评为"结果分析不充分"
6. **参考文献 < 8 篇**：评为"学术基础薄弱"
7. **论文页数 < 15 页**：评为"内容不够充实"

## 7.2 常见扣分点

1. **公式编号不统一**：有的有编号，有的没编号
2. **图表引用不规范**：图题不在图下方，表题不在表上方
3. **三线表格式错误**：表内有竖线，或表头表体无分隔线
4. **段落过于冗长**：一段超过 15 句，评委不愿意读
5. **空白过多**：图片后留白超过页面 15%
6. **字体/字号不一致**：不同部分格式不统一

## 7.3 套路化陷阱（国二论文通病）

| 套路化表现 | 为什么是陷阱 | 国一做法 |
|-----------|------------|---------|
| "问题分析→模型建立→模型求解→结果分析" | 像流水线，缺乏深度 | 每个环节结合题目具体展开 |
| 只放通用算法流程图 | 没有结合本题变量 | 流程图中的变量和步骤都来自本题 |
| 灵敏度分析只做 ±5% | 过于机械 | 结合参数实际不确定性范围 |
| 优点"模型精度高" | 空泛 | "交叉验证偏差仅 0.28%" |
| 缺点"模型不够精确" | 空泛 | "折射率做了常数近似，可采用 Sellmeier 方程修正" |

# 第八部分：与 mcm-paper-writing 的集成

## 8.1 调用时机

在 mcm-paper-writing 的每个章节写作前，应调用本 skill 获取该章节的写作指南。

## 8.2 指导优先级

1. **写作前**：获取章节指南 → 确认章节任务与证据 → 核对适用官方规则
2. **写作中**：检查公式编号与变量解释 → 确保图表被正文引用 → 维护数字来源
3. **写作后**：检查空洞表达 → 核对证据密度和篇幅分配 → 检查常见评阅风险

## 8.3 国一论文自检清单

```
□ 摘要是否包含每个子问题的方法+结果+数值？
□ 摘要页数、关键词和其他格式是否符合本届已读取的官方文件？
□ 每个关键公式是否在首次出现时说明变量、作用和适用条件？
□ 每个图表是否服务明确论点，并在正文中引用和解释？
□ 模型检验是否覆盖该模型最重要的失败风险？
□ 灵敏度分析是否覆盖高风险参数，并使用有来源的扰动范围？
□ 高不确定性结论是否采用适用的不确定性分析？
□ 优点是否用数据支撑？
□ 缺点是否配改进方法？
□ 结论数值是否与摘要一致？
□ 参考文献是否真实、相关、格式一致，并与正文双向对应？
□ 页数和文件大小是否符合本届官方规则？
□ 是否避免了所有"禁止表达"？
□ 排版是否可读、层级清晰且没有无意义填充？
```

# 第九部分：论文库使用

## 论文库位置

论文库不是固定磁盘路径。先检查用户提供的论文、当前工作区和已连接资料源；
只有实际存在并可读取的材料才能作为对标依据，并在输出中记录文件名、年份和来源。

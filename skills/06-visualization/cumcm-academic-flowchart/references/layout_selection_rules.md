# 布局选择、评分与主备方案

## 选择特征

综合 DAG/反馈边、入出度、并行分支、汇聚节点、小问数量、分组、标签长度、目标比例、论文位置、节点数、层级深度、中心性和阅读方向。禁止只按节点数量或随机选择。

## 典型规则

- 迭代闭环 → 环形、回字形或 U 形。
- 双源后融合 → 双流或 split-merge。
- 多问共享核心 → hub-spoke 或 central-model。
- 多问串并联 → 默认 question-architecture；每问内部必须有主方法、分支、汇聚和验证。question-swimlane 仅作为备用，不得退化成“一问一条横线”。
- 长流程且方形版面 → serpentine。
- 核心层与环境层 → concentric。
- 简单严格时序 → left-to-right 或 top-to-bottom。
- 主方法含多个子方法/组件 → method-framework、hierarchical-tree 或 layered-architecture。

只要任一建模问题没有分支节点或汇聚节点，就判定为“步骤链退化”，与节点数量无关。每问还必须覆盖至少四层语义深度。除真正严格时序图外，不得把这种布局选为数学建模方法框架。

## 候选评分

每图至少 4 个候选，复杂图 6-10 个。评分权重：

- 流程清晰度 25%
- 节点无重叠 15%
- 连线交叉控制 12%
- 语义顺序 10%
- 分组一致性 10%
- 标签可读性 8%
- 页面适配 8%
- 视觉平衡 6%
- 留白质量 6%

## 主备方案

主方案取最高综合分。备用方案必须保持相同节点和关键边、来自不同布局家族、单独通过质量检查且适合论文。差异度综合节点相对位置、主流向、空间拓扑、分组、中心位置和宽高比，默认 `layout_diversity_score >= 0.55`。

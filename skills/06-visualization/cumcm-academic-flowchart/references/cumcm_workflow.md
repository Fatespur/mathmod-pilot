## 输入与优先级

输入优先级为：用户明确指定 → 解题方案 → 论文草稿 → 赛题 → 源码 → 数据字段。只扫描指定文件、当前目录和明确的 `src/code/scripts` 子目录，不递归扫描无关大型目录。

先记录文件类型、来源和解析警告，再比较方案与源码：

- 数据入口、预处理、模型、目标函数、约束、求解器、指标和结果必须有来源。
- 方案与源码冲突时同时保留两种证据并写入 warning，不得擅自隐藏。
- 低置信度分类和模板补全节点必须标记 `inferred=true`。

## S0-S7 协作

| 阶段 | 上下游证据 | 本 Skill 行为 |
|---|---|---|
| S0-S1 | 任务书、题型、子问目标 | 读取题型与依赖；不替代问题分析 |
| S2 | 清洗数据、字段和质量报告 | 显示数据流与预处理，但不重算数据 |
| S3 | 模型、代码、参数与结果 | 提取模型语义、算法与输出 |
| S4 | 验证与敏感性结果 | 建立验证分支、诊断和闭环 |
| S5 | 图表生成 | 生成主备布局和全部格式 |
| S6-S7 | 论文与终审 | 交付 SVG、图题、质量报告和溯源 |

## 图表规划

先生成 `diagram_plan.json`。总体图只保留目标、数据、核心模型、求解、验证和输出。节点超过 24 或缩放后字体不足时，建议拆分为：

1. 总体技术路线图；
2. 单问详细流程图；
3. 模型检验与敏感性图。

## 输出与回退

核心路径为 `ModelingIR → Layout → Scene Graph → draw.io/SVG/PNG`。Graphviz、ELK、Mermaid 和 draw.io Desktop 只作为可选适配器。PNG 渲染器不可用时必须保留 draw.io/SVG、返回明确依赖错误并禁止生成空白或伪造 PNG。
